{%- comment -%} Renders one with a srcset built from the widths CI actually generated. The manifest is written by .github/scripts/resize_images.py, so we never point at a variant that is not on disk. An image with no entry (a brand new one, before CI has run) falls back to the original. AVIF is offered first and WebP second. A browser takes the first it understands, so anything without AVIF support quietly gets the WebP and anything without either gets the src. Params: src required, e.g. /assets/images/posts/foo.webp alt required, may be empty for decorative thumbnails sizes optional, defaults to the article measure loading optional, "lazy" for below-the-fold images priority optional, "high" for the LCP image {%- endcomment -%} {%- assign img_stem = include.src | split: "/" | last | split: "." | first -%} {%- assign img_base = include.src | split: img_stem | first -%} {%- assign entry = site.data.image_variants[img_stem] -%} {%- assign variants = entry.widths -%} {%- assign img_sizes = include.sizes | default: "(min-width: 40rem) 40rem, 100vw" -%} {%- capture srcset -%} {%- for w in variants -%} {%- if forloop.last and entry.full_webp != true -%} {%- comment -%} Original is already WebP, so it is the widest candidate. {%- endcomment -%} {{ include.src | relative_url }} {{ w }}w {%- else -%} {%- comment -%} Either a narrower variant, or a jpg/png original whose full-width WebP we generated. Both live at -.webp. {%- endcomment -%} {{ img_base | relative_url }}{{ img_stem }}-{{ w }}.webp {{ w }}w{% unless forloop.last %},{% endunless %} {%- endif -%} {%- endfor -%} {%- endcapture -%} {%- capture avifset -%} {%- for w in variants -%} {{ img_base | relative_url }}{{ img_stem }}-{{ w }}.avif {{ w }}w{% unless forloop.last %},{% endunless %} {%- endfor -%} {%- endcapture -%} {%- if variants and entry.avif %} {%- endif %}
